## Featured Project

### MOVA

**A fintech platform built around controlled access to money.**

MOVA is designed to help users move money away from their immediately accessible balance and release it according to predefined rules and schedules.

### Backend

- ASP.NET Core
- PostgreSQL
- Redis
- Hangfire
- Entity Framework Core
- MediatR
- Background processing
- Payment gateway integrations
- Bank payout processing
- Utility payment processing
- Authentication & authorization
- Transaction processing
- Automated testing

### Architecture

```text
Mova.Api
    ↓
Mova.Application
    ↓
Mova.Domain
    ↓
Mova.Infrastructure
    ↓
Mova.Shared

        +
     Mova.Tests
```

The project is structured around separation of concerns and maintainability, with dedicated application, domain, infrastructure, API, shared, and testing layers.

> Building financial software where transaction correctness, failure handling, and reliability matter.

## Engineering Focus

### Reliability

Designing systems that handle failures predictably, especially around external services, transactions, and asynchronous processing.

Investigating production incidents, tracing failures through logs and application behavior, identifying root causes, and restoring healthy system operation.

### Backend Architecture

Building maintainable APIs, services, workers, data-access layers, integrations, and domain logic with clear separation of responsibilities.

## Production Mindset

Software does not stop being software when it reaches production.

I care about what happens **after deployment**:

- What happens when an external API fails?
- What happens when a background job runs twice?
- What happens when a transaction is interrupted?
- How do we identify the root cause of an incident?
- How do we prevent the same failure from happening again?
- How do we improve performance without introducing unnecessary complexity?

That production perspective influences how I design backend systems.
